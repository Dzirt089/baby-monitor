# Конституция проекта «Радионяня» (Baby Monitor)

Версия: 1.0.0 | Ратифицирована: 2026-10-20 | Последнее изменение: 2026-10-20

## Преамбула

Проект создаёт приложение-радионяню для двух Android-телефонов в одной локальной Wi-Fi сети.
Приложение передаёт звук от детского устройства к родительскому. Ошибки в этой области
означают, что взрослый может не услышать ребёнка; поэтому надёжность и честная индикация
состояния важнее любых «удобных» компромиссов. Настоящая конституция фиксирует проверяемые
инженерные принципы, которым обязаны следовать все изменения.

## Основные принципы

### I. Приватность и безопасность по умолчанию (NON-NEGOTIABLE)

- Аудио не записывается на диск, не передаётся за пределы сопряжённой пары, не попадает в логи,
  телеметрию и crash reports.
- Локальная Wi-Fi сеть считается недоверенной: сопряжение, аутентификация signaling и защита
  media обязательны; cleartext HTTP/WebSocket для pairing/signaling запрещён.
- Долгосрочные private keys хранятся только в Android Keystore. Собственная криптография запрещена.
- Секреты, pairing tokens, fingerprints, имена детей и private IP не попадают в production logs.
- Проверяемость: security checklist в PR, review изменений pairing/key storage/TLS/transport,
  тесты на replay/expiration, проверка отсутствия секретов в логах и репозитории.

### II. Асимметрия ролей (NON-NEGOTIABLE)

- Child: работает микрофон, локальное воспроизведение и передача голоса родителя отсутствуют.
- Parent: работает воспроизведение; микрофон не запрашивается и не открывается, разрешение
  RECORD_AUDIO не публикуется и не используется.
- Один APK содержит обе роли; роль выбирает пользователь явно.
- Проверяемость: domain/application тесты инвариантов, проверка manifest, device-тест на отсутствие
  микрофонных разрешений у Parent-сценария.

### III. Строгое направление зависимостей

- Domain не зависит ни от чего, кроме BCL. Application зависит только от Domain.
  Infrastructure — от Application и Domain. Platform.Android — от Application и Infrastructure.
  App собирает всё вместе.
- Android/WebRTC/NSD-типы не пересекают границы Application/Domain contracts.
- Проверяемость: architecture tests в CI на каждом PR; такие тесты нельзя отключать «на время».

### IV. Надёжность и наблюдаемость важнее минимальной задержки

- Потеря heartbeat и отсутствие media flow различаются и диагностируются раздельно.
- Reconnect-политика — один объект конфигурации с exponential backoff и jitter; все retry loops
  принимают CancellationToken и имеют владельца.
- Parent подаёт локальную тревогу после настроенного порога потери связи независимо от ответа Child.
- «WebRTC connected» не равно «пользователь слышит звук».
- Проверяемость: unit-тесты состояний/retry с fake TimeProvider, device-тесты потери сети,
  метрики (underruns, packets, RTT, jitter, buffer depth) в диагностике.

### V. Spec-driven delivery и честность проверок

- Порядок работы: constitution → spec → clarify → plan → requirements checklist → tasks →
  consistency analysis → implementation → convergence.
- Спецификация описывает «что и зачем», plan — «как», tasks.md — единственный task ledger.
- Нельзя объявлять проверку пройденной, если она не запускалась. Hardware/device-сценарии
  считаются проверенными только после фактического прогона с фиксацией устройства и serial.
- Проверяемость: tasks.md отражает фактические чекбоксы; PR содержит раздел проверок;
  CI logs и artifacts являются источником истины для build/test.

### VI. Безопасные границы изменений

- Любое изменение pairing, key storage, TLS, transport, audio capture/playback или foreground
  service обязано описать threat/trust boundary, failure mode и тесты.
- Новый NuGet/Gradle-пакет требует обоснования: зачем, почему недостаточно BCL/платформы,
  лицензия, поддержка, влияние на APK, security history.
- Медицинские утверждения, гарантии безопасности жизни и «полностью автоматическое обновление»
  не допускаются.
- Проверяемость: PR checklist, ADR при изменении решения, review зависимостей.

## Дополнительные ограничения

- Ожидаемые исходы use case возвращаются типизированным Result, а не исключением.
- В Domain запрещены логирование, файлы/БД, JSON, DI, сокеты и асинхронность без доменной нужды.
- Запрещены пустые catch, fire-and-forget без владельца, .Result/.Wait, async void вне UI events,
  DateTime.Now/UtcNow вместо TimeProvider, unbounded real-time buffers.
- Состояние сессии моделируется одним конечным автоматом, а не набором несогласованных bool.

## Рабочий процесс

1. Для значимой функции создаётся каталог .specify/specs/NNN-slug с spec.md, plan.md, tasks.md.
2. Clarify-вопросы задаются до плана; противоречия с конституцией решаются в пользу конституции.
3. Requirements checklist проверяется отдельным ревьюером, а не автором изменений.
4. Реализация не начинается, пока не приняты релевантные ADR (если решение архитектурное).
5. После реализации обновляются tasks.md, roadmap.md и ADR; CHANGELOG — только для выпущенных
   пользовательских изменений.

## Governance

- Конституция приоритетнее стиля и локальных договорённостей; AGENTS.md конкретизирует её для
  разработки, но не ослабляет.
- Изменение конституции — отдельный PR с обоснованием и версией (SemVer: MAJOR — несовместимое
  изменение принципа, MINOR — новый принцип/раздел, PATCH — уточнение формулировки).
- Нарушение NON-NEGOTIABLE принципа блокирует merge.
- История изменений: ратификация 1.0.0 — создание конституции в bootstrap-фазе.
