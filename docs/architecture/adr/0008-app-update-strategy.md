# ADR-0008: Стратегия обновления приложения

- **Статус**: Proposed (решение до 008-release-readiness)
- **Дата**: 2026-10-20
- **Решение принимает**: владелец продукта + архитектор
- **Связанные документы**: [ADR-0009](0009-android-versioning.md), [README.md](../../../README.md) (release-процесс)

## Контекст

Релизы публикуются по SemVer-тегу как GitHub Release с подписанным APK. Нужно определить, как
пользователь получает обновления. Silent installation для обычного Android-приложения невозможна;
загрузка APK из GitHub Release — не «автоматическое обновление».

## Решение (предлагаемое к проверке)

Bootstrap реализует только сборку/публикацию по тегу, без установки на телефоне. Стратегия
обновления выбирается отдельным ADR до первого публичного релиза; кандидаты:

- **A. Google Play / Internal testing + Play In-App Updates** — если приложение будет
  распространяться через Play; требует Play Console, подписи Play App Signing.
- **B. GitHub Release metadata + system installer** — приложение проверяет release metadata,
  предлагает скачать APK и передаёт установку Android system installer. Обязательны: проверка
  package name, monotonic versionCode, тот же signing certificate, SHA-256, явное согласие
  пользователя, запрет обновления во время активной monitoring session.

Общие требования: update никогда не запускается во время активной сессии; пользователь явно
соглашается; артефакт проверяется до установки; нет background/silent self-install.

## Рассмотренные альтернативы

| Альтернатива | Плюсы | Минусы | Статус |
|---|---|---|---|
| A. Play In-App Updates | стандарт, безопасность магазина | нужен аккаунт Play/сборы, задержки review | кандидат |
| B. GitHub Release + system installer | без магазина, контроль владельца | ручное подтверждение, риск подмены при плохой проверке | кандидат |
| Собственный updater/silent install | «удобно» | невозможно без privileged прав, нарушает security | отклонено |
| Без обновлений | просто | устаревшие версии с известными дефектами | нежелательно |

## Последствия

- Первый release не блокируется этим ADR только при отсутствии публичного распространения.
- Update UX и проверки — отдельная feature с тестами и threat model (подмена APK, downgrade).
- GitHub Release notes/CHANGELOG служат источником пользовательских изменений.

## Проверка и критерии пересмотра

Перед первым публичным релизом ADR переводится в Accepted с выбранным вариантом, либо release
явно позиционируется как side-load без обещания обновлений.
