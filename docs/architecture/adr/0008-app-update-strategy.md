# ADR-0008: Стратегия обновления приложения

- **Статус**: Accepted (2026-11-08: для тестовых/MVP-сборок v0.x выбран side-load APK из GitHub Release без авто-обновления; публичное распространение и updater — отдельное решение)
- **Дата**: 2026-10-20
- **Решение принимает**: владелец продукта + архитектор
- **Связанные документы**: [ADR-0009](0009-android-versioning.md), [README.md](../../../README.md) (release-процесс)

## Контекст

Релизы публикуются по SemVer-тегу как GitHub Release с подписанным APK. Нужно определить, как
пользователь получает обновления. Silent installation для обычного Android-приложения невозможна;
загрузка APK из GitHub Release — не «автоматическое обновление».

## Варианты (историческая фиксация, см. принятое решение ниже)

Bootstrap реализует только сборку/публикацию по тегу, без установки на телефоне. Кандидаты
(принятое решение для v0.x — ниже, критерии пересмотра — в конце):

- **A. Google Play / Internal testing + Play In-App Updates** — если приложение будет
  распространяться через Play; требует Play Console, подписи Play App Signing.
- **B. GitHub Release metadata + system installer** — приложение проверяет release metadata,
  предлагает скачать APK и передаёт установку Android system installer. Обязательны: проверка
  package name, monotonic versionCode, тот же signing certificate, SHA-256, явное согласие
  пользователя, запрет обновления во время активной monitoring session.

Общие требования: update никогда не запускается во время активной сессии; пользователь явно
соглашается; артефакт проверяется до установки; нет background/silent self-install.

## Рассмотренные альтернативы

| Альтернатива | Плюсы | Минусы | Статус |
|---|---|---|---|
| A. Play In-App Updates | стандарт, безопасность магазина | нужен аккаунт Play/сборы, задержки review | открыто до решения о публичном распространении |
| B. GitHub Release + system installer | без магазина, контроль владельца | ручное подтверждение, риск подмены при плохой проверке | **принято для v0.x side-load** |
| Собственный updater/silent install | «удобно» | невозможно без privileged прав, нарушает security | отклонено |
| Без обновлений | просто | устаревшие версии с известными дефектами | нежелательно |

## Принятое решение (2026-11-08)

Для сборок v0.x, которые распространяются владельцу для device-тестов, выбран **вариант B в
минимальном виде**: подписанный APK публикуется как GitHub Release, пользователь вручную скачивает
и устанавливает его (sideload), обновления **не проверяются и не устанавливаются автоматически**.

Правила:

- Обновление — только вручную: скачать новый APK из GitHub Release, проверить SHA-256, установить
  поверх (same signing certificate). Приложение не выполняет сетевых запросов за обновлениями и не
  предлагает self-install.
- Приложение никогда не инициирует установку/обновление; активная monitoring session не прерывается
  фоновым updater (его нет).
- Публичная дистрибуция (Google Play/стор) и in-app update UX остаются **открытым решением** и
  требуют отдельного ADR до любого публичного релиза.
- Для тестовых сборок допустимо использовать тот же постоянный release keystore (тот же
  сертификат) — это обеспечивает установку обновлений поверх без переустановки.

## Последствия

- Первый release не блокируется этим ADR только при отсутствии публичного распространения.
- Update UX и проверки — отдельная feature с тестами и threat model (подмена APK, downgrade).
- GitHub Release notes/CHANGELOG служат источником пользовательских изменений.

## Проверка и критерии пересмотра

Accepted для тестовых/MVP-сборок v0.x (side-load без авто-обновления, см. принятое решение).
Пересмотр обязателен при: решении о публичном распространении (Google Play/стор), появлении
in-app update UX, изменении политики обновлений или требований безопасности; такое решение
оформляется отдельным ADR. Для v0.x release явно позиционируется как side-load без обещания
обновлений.
