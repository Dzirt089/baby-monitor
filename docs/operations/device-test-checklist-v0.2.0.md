# Device-тест 0.2.0 (2 Android-устройства)

**Цель**: проверить на реальных устройствах уже реализованное (pairing UI, камера/QR, trusted
devices, foreground service, диагностика) до реализации звука (005 phase 2).

**Важно**: 0.2.0 **не передаёт звук** и не устанавливает сетевое соединение — это ожидаемо.
«Радионяня работает» можно будет сказать только после 0.3.0 и подтверждения слышимости владельцем.

## Подготовка

1. Оба устройства: одна Wi-Fi сеть (2.4/5 ГГц — не важно), интернет нужен только для скачивания APK.
2. На компьютере открыть GitHub → репозиторий Dzirt089/baby-monitor → **Releases** → release
   v0.2.0 → скачать io.github.dzirt089.babymonitor-Signed.apk и app-release.apk.sha256.
3. Проверить SHA-256 скачанного APK (PowerShell: `Get-FileHash .\io.github...-Signed.apk -Algorithm SHA256`)
   и сверить с файлом checksum.
4. Передать APK на оба устройства (кабель/облако) и установить (разрешить установку из неизвестных
   источников для файлового менеджера).
5. Оба устройства должны иметь **один и тот же** APK из одного Release (одинаковый сертификат).

## A. Установка и старт

- [ ] На обоих устройствах приложение устанавливается и запускается без краша.
- [ ] Первый экран — выбор роли («Я ребёнок» / «Я родитель»), роли явно видны.
- [ ] В «Настройки → Приложения → Радионяня → Разрешения» Parent-устройство **не запрашивает**
      микрофон; Child может запросить уведомления/микрофон только по действию «Запустить мониторинг».

## B. Сопряжение (главное в 0.2.0)

Устройство A — Child, устройство B — Parent.

- [ ] A: «Я ребёнок» → экран сопряжения → появляется QR-приглашение и таймер ~5 минут.
- [ ] B: «Я родитель» → «Сканировать QR ребёнка» → запрос CAMERA → превью камеры открывается.
- [ ] B сканирует QR с экрана A → на B появляется 6-значный код и QR-ответ.
- [ ] A: «Сканировать ответ родителя» → сканирует QR с экрана B (на A тоже запрос CAMERA).
- [ ] На A появляется **тот же** 6-значный код, что на B.
- [ ] Подтвердить код на обоих устройствах → оба показывают «Сопряжение завершено» и доверенное
      устройство (роль peer, короткий fingerprint, дата).
- [ ] Нажать «Забыть устройство» на одном → подтвердить → экран возвращается к сопряжению
      (можно снова создать приглашение/сканировать), запись исчезает из диагностики.
- [ ] «Сопрячь заново» → новый QR создаётся, повторное сопряжение проходит.
- [ ] Негатив: сканировать посторонний QR (например, QR сайта) → typed-ошибка «QR повреждён или не
      поддерживается», без краша; приглашение живёт 5 минут, после истечения — ошибка expired.
- [ ] Повернуть устройство/уйти с экрана во время сканирования → камера останавливается, без краша.

## C. Foreground service / уведомление

- [ ] После сопряжения «Перейти к мониторингу» → «Запустить мониторинг»: появляется постоянное
      уведомление «Радионяня: ребёнок/родитель / Мониторинг активен» с кнопкой «Остановить».
- [ ] Уведомление остаётся при выключенном экране; по «Остановить» сервис останавливается.
- [ ] «Остановить» в приложении → состояние «Остановлен», уведомление исчезает.
- [ ] Роль Child запрашивает RECORD_AUDIO только при старте; Parent — не запрашивает.
- [ ] Убрать приложение из недавних (Activity уничтожена) при работающем сервисе — сервис
      продолжает работать (проверить уведомление).

## D. Диагностика

- [ ] Экран «Диагностика» (из экрана мониторинга): роль, состояние foreground-сессии, версия
      приложения (0.2.0), доверенные устройства (роль/fingerprint/дата).
- [ ] Данные не меняются после ротации; при возврате на экран — обновление.
- [ ] В логах нет QR payload/verification code/секретов (если снимаете logcat).

## E. Что записать в отчёт

1. Модели устройств и версии Android (например, Pixel 7 / Android 14; Xiaomi … / Android 13).
2. Что прошло/не прошло по пунктам (можно номерами), скриншоты экранов **без QR-кодов**.
3. Для сбоев: шаги воспроизведения + logcat (если есть adb):
   `adb logcat -d | findstr /I "BabyMonitor AndroidRuntime"`
4. Замечания по UX: размер QR, яркость, скорость фокуса камеры, понятность текстов, TalkBack.

## Ожидаемые известные ограничения (не дефекты 0.2.0)

- Звук не передаётся, сетевого соединения после сопряжения ещё нет (signaling — 0.3.0).
- Авто-обновления нет: новые версии — вручную с GitHub Releases (ADR-0008).
- Только 2 устройства и одна LAN; guest Wi-Fi/AP isolation не поддерживаются (ошибки — в 005/007).
